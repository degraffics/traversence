# Working notes for Claude sessions on this repo

> **Silent by default (R4, Jason 2026-11-27, enforced 2026-11-28).** Nobody reads this session's chat: every word
> written there costs usage. Write no progress notes, plans, recaps or summaries in your own chat. Use tool calls,
> commits and one short message to the session manager per result (what's done, its link, what's needed). End each
> turn with no text, or one line at most. The CEO session is the only session that writes to Jason.

This repo (`degraffics/traversence`) is the durable record of Traversence's governance and technical docs: charter, PRD,
commercial, architecture, brand, phases, regions, routes, workflow, future-considerations, `decisions/*.md`,
`traversence-platform-spec.md`, and Claude Docs exports in `claude-docs/`. The site's code lives on the server and in
OneDrive, mirrored to `degraffics/traverse-3way-sync` (below). Rules marked "every build" apply to every delivery.

Each rule below is one line; its full text is in `handoffs/builder-playbook.md`'s appendix, §R<n> (read it before
working in that area). The line and the full text say the same; where they seem to differ, the full text governs.

- **R1. Pushing from a cloud session:** Push with plain `git push`/`git pull` (the proxy adds the credential). If refused as "not in this session's authorized repository set", don't retry or route around it: commit locally and tell Jason his options. Any session may `add_repo` `degraffics/traversence` or `degraffics/traverse-3way-sync` (shallow, sparse) without asking.
- **R2. One copy: all work ends up in `main` (Jason, 2026-11-01): every session:** `main` is the one copy: start from the latest `origin/main`; finish with a `claude/…` branch, one open PR at a time, merged; check `git merge-base --is-ancestor`, say plainly the work is in `main`, and never call work saved when it's only on a branch.
- **R3. Build on what's there (Jason, 2026-11-10): every build:** Read an area's decisions and live code before changing it; extend or replace in place, never drop (the zip check blocks drops; `--drops` only with Jason's OK). **Never invent what's already set:** `git grep` decisions and live code first and cite the source; a gap is flagged with suggestions; an improvement is "Suggest a change to <decision>: …", never applied as decided.
- **R4. Work silently (Jason, 2026-11-27): every session:** Sessions write nothing in their own chat (see the box at the top): work goes into commits, hand-offs, release records and short messages to the session manager. Only what needs Jason goes to him, through the CEO.
- **R5. Launch first: no gate, no build (Jason, 2026-11-27; 0181 §2): every session, until 0181 §1's six gates pass:** Until 0181 §1's six gates pass, every ticket names its gate, a live harm, the revenue goal or the money it protects (indirect links stated); otherwise it's logged, not built. No new tooling, meters, board features, check refinements or process releases unless one blocks a gate; releases go live once their checks pass (Jason, 2026-11-28; Tier 4s and content-removing data changes still in his daily batch); no new sessions before launch.
- **R6. The session manager (Jason, 2026-11-13): every session:** A standing session manager watches the others (context, restarts, cost, release clashes, syncs, Railway). One session per area, about three at once; a multi-phase build stays in one session until live, except a hand-off when it grows too large (reviewed, then a fresh session, the old archived). Finished sessions are archived on the check; one waiting on Jason never is. Goals and records live with the roles in the Work queue (owner, measure, due date, decision), not in a session.
- **R7. End to end, verified, before anything ships (Jason, 2026-11-21): every build:** Before code is done: it fits the agreed boundaries and one state model; every state transition and side effect is mapped; the UI sits where the problem is and tells the truth; happy path, failures, edge cases and recovery are tested. Live data only through the test accounts and `live-read.yml`; live-site actions only on Jason's call; anything people see goes to the Design reviewer first (1280 and 390).
- **R8. Build sessions follow the playbook (Jason, 2026-11-18): every build:** Before the first release, read `handoffs/builder-playbook.md` (fixes in place, a way back for every action, the phone at 390, words kept true, one coherent release, `send.py`'s refusals fixed at the cause) and its principles.
- **R9. Keep this file lean:** This file and `README.md` load in full every session: one short rule per point, the detail in the decision or the playbook it cites; remove rules a later decision replaces; keep the README a short map.

- **R10. The 3-way sync: server ⇄ OneDrive, recorded in GitHub (Jason, 2026-10-28): every build:** `degraffics/traverse-3way-sync` mirrors the server and OneDrive (`sync-storage/`, `sync-app/`, `sync-trvgo/` on its `main` = what's live). Every build is a release through git (`send.py`, zip check, delivery log, `releases/inbox/`), only files that differ byte for byte; claim before writing (`checkout.py`), start every file from the newest live copy, fetch again before zipping; one release at a time, the sync after each publish, run by Claude, one sync run at a time; staging is safe mode (0165: R13, R14). Never zip `bootstrap-super-admin.php` or anything "Removed"; dotfiles and `app/storage/` never sync.
- **R11. Files used once, and the archive (Jason, 2026-10-28): every build:** Migrations run themselves, oldest first, must be safe twice and need no person; `UPDATE`/`DELETE` needs `"data_reason"`. Test files and one-off scripts never go in `website/` or `app/`. Archived pages are listed in `archive.md`; dead code (nothing calls it on the live mirror) is deleted.
- **R12. The crawler, research and guides: decisions/0164 rules: every build:** `decisions/0164` is the one rule book for the crawler and what it feeds (curators not controllers; tell the story, never the way in; never overwrite a person's words; the licence decides; nothing private to Gemini's free tier); its numbers live in `decisions/0163`.
- **R13. Folders: website/, app/, trvgo/ (decisions/0069, 0094):** `website/` is the web root (pages and endpoints only); `app/` is never served (`lib/`, `data/`, `ui/`, `migrations/`…); `trvgo/` is trvgo.us's router and storefronts (0139). Zips hold real paths; notes folders go in neither.
- **R14. The admin (decisions/0109): every build:** 10 modules at `/admin/<module>/<section>[/<id>]` from `app/admin/manifests.php`, one endpoint; no admin page outside the manifests; stages are workflows; access through `Access::can()`, disallowed actions greyed with the reason; another module's tools open in a drawer.

- **R16. Keep the FAQ current (decisions/0057): every build:** Every build adds or updates `faq.md` entries for what changed, from a visitor's view ("coming" where not built), shipped in the zip; check `faq.php#` anchors before rewording.
- **R17. Every action is a task: see it, do it, confirmed, next (Jason, 2026-11-23): every page:** Every action is a task: see it, do it (one button where it's shown), done and confirmed by a real check, then the next step only within a process.
