# ADR 0034: Promotional/Trial Tier Grants — Comped Access Independent of Payment, Review-Gated Continuation

**Status:** Accepted (2026-09-25)

## Context

SJ Portables needs live Cornerstone-tier access — specifically multi-location inventory management, gated to Strategic/Cornerstone by `decisions/0032` — to actually test the site and features being built for them. Per direction, this platform is a live, paying-customer product, not a sandbox with the gates turned off for a favored account: SJ Portables gets Cornerstone access as a promotional arrangement, at no cost for a period, not as a permanent bypass of the tier logic. That distinction needs a real mechanism, because it will come up again — SJ Portables won't be the only trial, beta, or comped account this platform ever has.

## Decision

**Tier gates check an account's effective tier, never how that tier was reached.** Multi-location inventory management, AI-content quotas, White-Glove eligibility, and every other tier-gated feature keep checking the same thing they already check — the account's current tier — regardless of whether that tier came from a paid subscription or a promotional grant. This keeps every existing and future gate check completely generic; only how an account's tier gets set differs, never how it's enforced.

**A promotional/comped tier grant is real account state, not a hack.** An account can hold a tier it isn't paying full price for, but that has to be a recorded, deliberate state — which tier, granted from when, and reviewed by when — not an undocumented manual override that leaves no trace of why the account has access it isn't paying for.

**The grant is per listing, per direction 2026-09-25, matching `decisions/0035`'s per-listing Subscription model.** SJ Portables' three locations each carry their own promotional Cornerstone Subscription record, not one account-wide grant covering all three — consistent with each listing needing its own subscription for tier-gated features like `decisions/0032`'s catalog cap and `decisions/0036`'s Location Group eligibility. Continuation review (below) happens per listing too, though in SJ Portables' case all three will practically be reviewed together as one trial.

**Continuation is a real decision point, per direction — not automatic in either direction.** SJ Portables' promotional Cornerstone access is explicitly contingent on their user experience during the trial: someone reviews it and decides to convert to a paid tier, extend the trial, or step the account down — it doesn't silently lapse into losing access, and it doesn't silently continue forever by default either. The same review-gated pattern should govern any future promotional grant, not just this one.

**A promotional/trial-tier account does not accrue public SEO value during the trial, per direction.** Any generated site pages or listing content tied to a promotional grant carry `noindex, nofollow` directives while the account remains in promotional status — search engines are told not to index the pages or follow their links. This closes a real gap `decisions/0033`'s SEO framing would otherwise leave open: that ADR ties real inbound-authority value to Cornerstone-tier deployment, and a trial account hasn't earned that value through payment yet — it shouldn't accrue it for free during a comped period, only to walk away at the end of the trial having banked the SEO benefit regardless. Indexing/following opens up normally once the account converts to paid or the review workflow above confirms continuing status. This applies to SJ Portables' build now and to any future promotional grant generally, not as a one-off carve-out.

## Consequences

`commercial.md`'s tier model gains a second dimension — how a tier was granted, separate from the tier itself — which needs its own account-level fields (a grant source, and a review/expiration point) and its own lightweight admin review workflow; neither is designed yet, flagged here rather than assumed. `decisions/0035` is where those fields formally live, on the Subscription record. The build guidance already given to the SJ Portables thread stands unchanged: build the real Strategic/Cornerstone gate for multi-location inventory management, don't hardcode it always-on for their account. This ADR is what makes that gate check correctly gate SJ Portables' account when appropriate, since their Cornerstone status is real, recorded account state — a promotional grant, not an exception the code has to know about. The `noindex, nofollow` rule above also needs a concrete hook — a flag the page-rendering/site-generation layer checks against the account's promotional status, not a manual per-account toggle someone has to remember to flip — and this is the first place `decisions/0033`'s SEO-value claim and a real gate condition have to meet in actual implementation.
