# 0066. Public data, the Discovery funnel, and expansion that grows on its own

Date: 2026-10-07
Status: Accepted

## Context

Jason's Western States list (11 states, 1,961 places by county) and the Discovery Engine funnel (Macro → Region → Hub →
Cluster → Anchor → Experience, with the pillars Outdoor Exploration, Culture & History, Food & Drink and Lifestyle,
plus the Events and Resources layers) raised four questions: what the list is for, whether places need descriptions,
how tribal land is presented, and how new areas open.

## Decision

1. **The geography is existing structure, not a build-out.** State, county, city and ZIP are common knowledge and
   already in our `zip_coordinates` table (41,490 ZIPs). The Western States list is cleaned against it as a
   reference.
   - **The funnel is Hub → Region → Cluster → Anchor (→ Experience).** Region and Cluster are groupings that funnel a
     Hub's anchors into bite-size displays, curated by Traversence. Someone who knows the anchor can jump to it
     straight from the Hub.
   - **County is geography, not a funnel level.** Each anchor sits in a county; county is a way to search and group.
2. **No stored descriptions.** Each level's guide is generated by the system (the funnel's dynamic guide
   templates), eventually as a crawler subroutine, not typed into the list.
3. **A clear line between public and private data. This is the standard.** Everything public is presented: established boundaries, key
   resources and infrastructure, public listings and publicly relevant information, on a nation's land too.
   Anything sensitive or private (a sacred or restricted site; anything about a user or owner) is shown only with
   that owner's or user's explicit say. This is the same privacy philosophy as the rest of Traversence. When a nation
   owns its listings and experiences (the nation tools), it decides what more is shown; public key infrastructure
   stays public. Sensitive means locations specific to the nation: they are held from public view until the nation has
   control measures in place (the nation tools).
4. **Expansion is organic.** The hierarchy is already in place; nothing waits on an "open this area" step. Search
   (what people ask, where) sets the user-guided targets. The crawler is used by admins and regional operators to
   develop a targeted area further. Admins can push data to propagate, and curate Region → Anchor for the areas
   Traversence chooses to refine.
5. **Search reads a place in the words as the what, not a change of where.** A town, county, state or region in the
   words answers for that place without changing the set location. Search predicts what the person likely wants
   there and lets them choose, change or try again. The set location changes only when they choose to get local.

## Consequences

- **The cleaned list** (`Western-States-Places-clean.xlsx`) is a reference for anchors by county, with ZIPs and a
  middle point, and empty Hub, Region and Cluster columns to curate. California is filled in from our ZIP table
  (1,240 places).
- **Tribal land, built (2026-10-07):** `Landmarks::decide()` shows public places on a nation's land. It holds names
  that may mark a sacred, burial or protected site (anywhere) and a nation's springs
  (`NATION_SENSITIVE_CLASSES`). Editors add public places on a nation's land without the nation's page; opening a
  held one needs the nation's word. `api/migrations/2026-11-05_landmarks_public_standard.sql` shows the landmarks
  that were held only for being on a nation's land. CLAUDE.md carries the standard.
- **Counties in search, built:** "navajo county", "King County, WA" and "pizza apache county az" are read as places
  (`UniversalSearch::countyNamed`). The search covers every ZIP in the county (`SearchIndex::whereSql`).
- **Place card, built:** a place on its own ("seattle washington", "navajo county") asks what about it: things to do,
  places to eat, places to stay, moving there, plan a trip, and **Make it my place**. That last one is the only thing
  that changes the set place. A name only ("springfield") asks **Which Springfield?** when nothing else is found.
- **Search demand, built:** the place, what for and where it led, by day, counts only (`search_demand`,
  `SearchDemand`). It records searches people acted on, and taps on OpenStreetMap rows, Google Maps links and
  place-card choices. Admin → Search → **Search demand** shows it as state → county → town.
- **Crawler targets, built:** from that page, **Develop with the crawler** queues a town and a kind of business
  (`crawl_targets`). The worker finds the businesses (OpenStreetMap as the lead), checks each on its own website and
  stages them in Listing Intake, held for a person (`hold`, never auto-published).
- **Crawler sourcing, built:** when a business's own website names it, its name, address, phone and hours are sourced
  to the website (the phone from the site when it shows one). What the site doesn't show stays the OpenStreetMap lead,
  marked as such, for a person to check.
- Run `2026-11-05_landmarks_public_standard.sql` and `2026-11-06_search_demand.sql` once.
- 2026-10-07, later: a place named in the words leads while typing even with a place set ("Seattle Washington" with
  St. Johns set shows Seattle's place card). Words that are only a place get no situation guesses. A real word or a
  town's name is never typo-corrected into a situation word (`Situations::properWord`: "seattle" was read as
  "shuttle", which offered Need a ride).
- 2026-10-07, later: a town's name on its own that nothing on Traversence matches ("Seattle") gets that town's place
  card, while typing too. A name used in several states asks which one. A name that does match something ("Lyman": Lyman
  Lake) is left to its results.
- 2026-10-07, later: nothing in place reading is per town. Every rule reads the national `zip_coordinates` table (any
  town, county or state, one to three words). Checked on the full table with towns never seen before: Bozeman, Moab,
  Twin Falls, Lake Havasu City, Maricopa County, "Which Portland/Santa Fe/Grand Junction?". Town names now match
  whatever their punctuation or spacing ("coeur d alene" is Coeur d'Alene, "winston salem" is Winston-Salem).
